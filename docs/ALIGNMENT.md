# Alignment while editing

Moving and resizing controls attracts to nearby sibling edges, centers and spacing guides. Attraction uses five document units at every zoom level. Center alignment takes priority while moving; the active edge takes priority while resizing. Overlapping guides resolve in sibling order. Containers use their shared content layout for inward spacing.

Hold Command on macOS or Control on Windows/Linux to bypass attraction. Shift constrains movement to one axis or preserves resize proportions. Alt also bypasses resize attraction. Fast movement temporarily suppresses attraction using recent pointer-event distances. Snap to 10 remains a separate explicit grid mode.

Multiple selected controls move with a shared delta. Locked controls do not move but remain alignment targets. Nested editing uses the current group's siblings in global coordinates. Guides are transient; they are never saved or exported. Releasing commits one Undo step. Escape or focus loss cancels the gesture. Pointer presses are retained across render frames so quick completed drags are not discarded.

Phone and Smartphone retain the ordinary 16-unit exterior spacing targets in addition to their interior content guides. Smartphone adds interior guides only in Fit; Tablet uses ordinary outer targets. Interior guides remain attached to the visible frame when another sibling moves to its left.

Hold Option/Alt while moving to preview copies, leaving the originals in place. Changing the modifier without moving the pointer switches between copy and move. Copies attract to the original controls as well as ordinary sibling targets. Shift constraints and explicit grid/bypass behavior still apply. Release records one Duplicate controls history step; Escape or focus loss restores the document, selection and existing Redo. Only movable selected roots are copied; descendants follow the ordinary duplication unlocking policy. Component instances retain their shared source; source placements duplicate independent definitions and notes. Inside a component instance, structural duplication is unavailable and the gesture remains a move.

Library insertion has its own pointer-following preview and is separate from existing-control alignment. Additional control-specific boundaries, arrow endpoints, keyboard-only guides, remaining autoscroll cases remain follow-up work. Exact native guide appearance and Windows/Linux interaction acceptance are unverified.

Checks cover geometry priority and thresholds, target order, center resize limits, event-distance suppression, locked neighbors, group coordinates, window content boundaries, multi-selection, zoom, modifier changes, focus cancellation, Undo, and complete or split-frame native event delivery.

With editor markup hidden, sibling group snap targets use the union of unmarked descendant bounds intersected with the existing crop. This does not shrink movable selection handles or change pointer movement/resizing geometry. Zero-content group bounds retain a zero extent; local component overrides are resolved before calculating targets. `tests/markup_geometry.rs` covers this distinction. Native held snapping remains separate acceptance work. Locked selection outlines retain the complete group frame; visible bounds apply to inspector and arrangement calculations, not that decoration. Hidden arrangement offsets and sampled native Left/Center behavior are recorded in the markup specification and external `editor-markup-arrangement-current/report.md`.
