# Reusable components

Select one control or group and choose **Make component** in the inspector. The Components sidebar lists definitions. Click a name to edit its shared source or + to insert an instance. **Back to wireframe** returns to the page. Shared source edits update instances throughout the project.

Double-click an instance, press Enter on it, or choose **Edit this instance** to work on local children. Enter nested groups the same way. The toolbar identifies local editing; Escape or Exit component level returns one level. Text, appearance, movement and supported size edits affect only that instance. The inspector marks locally changed fields and offers **Reset** to inherit the source again.

**Reset local changes** clears all local changes on a selected child or group. **Reset instance overrides**, available on a selected instance outside its contents, restores the whole instance. Reset leaves the source intact and can be undone. **Detach component** converts an instance to an ordinary group with its current effective values.

Source definitions retain control structure. Add/delete/group/reorder operations inside an instance report that the source must be edited. Copying a local child preserves its current effective values; leave the instance before pasting new content. Position locks restrict geometry and structural edits while leaving text and appearance editable. Source-owned locks do not propagate into ordinary page instances; instance-local and ancestor locks retain their own scope.

Sources can move between libraries through navigator dragging or their Move to library menu. Shared references and source appearance survive the one-step transfer. See [source movement](SOURCE-MOVEMENT.md).

## Deleting a source

Open a component source, clear the selection, and choose **Delete component source** in its inspector. Existing instances remain as150×150 missing-component placeholders. Their references and local changes are preserved in the saved file. Undo restores the source during the current session; reopening does not retain Undo history. Missing instances can move, copy or be deleted, but their size is fixed and source editing/reset/detach is unavailable. A parent with missing descendants cannot be detached. Copying missing references assigns fresh missing IDs to prevent unrelated destination components from being substituted.

Native macOS checks cover deletion, Undo restoring resized/local content, Redo, saving and reopening. Four regression tests additionally cover nested references, alternates, crop preservation, context recovery, shared SVG/PNG rendering, allocator/clipboard collisions and no-op Ungroup. ## Empty components and groups

Removing every source child keeps the definition and shows an **Empty component** frame on its instances. Add new source content to populate them again. Local changes for removed child IDs remain stored but do not attach to fresh children. Empty instances can be detached into ordinary empty groups. Empty groups remain selectable and editable; enter them and add a first child through the library or Quick Add. Empty fallback dimensions are150×150. Position, lock state and stored crop data remain intact; inherited ancestor clipping still applies.

Empty/populated transitions preserve explicit layer position. Older files may omit empty groups in their paint order; they load unchanged and newly visible empty groups draw last. New edits include them as paint units. Root pages and source workspaces with no content remain blank. Native checks and regression coverage are recorded in SESSION-SPEC.md.

## Source placement actions

Library source placements represent canonical groups. Canvas placement duplication creates an independent source with a fresh identity, the same name and child structure, preserved crop, and a ten-unit offset on each axis. Navigator duplication instead generates a unique copy name. Both duplication paths clear locks in the copied literal tree while leaving originals and shared instance dependencies unchanged. Neither path creates an ordinary instance of the existing source. Navigator copy names append “copy”, then “copy 1”, “copy 2” as needed within the owning library; duplicating an already named copy appends another suffix.

Grouping two source placements replaces their top-level availability with a fresh outer source containing ordinary nested groups. Existing page references to the former sources remain stored and display missing placeholders. Undo restores the original identities and resolves those references again. Ungroup is a different operation: the extracted groups receive fresh source identities, preserve their contents/appearance/positions, and do not reconnect old references. Keep these operations atomic across definitions, ownership, library contents, allocation and history. A generic group operation on placement instances cannot supply this behavior.

A locked source can be entered. Explicit source entry shows full uncropped child artwork. Children without their own locks remain selectable through the canvas and Select All. The source owner lock prevents movement and makes geometry read-only; Cut, Delete, Group and Ungroup are unavailable for that locked selection. Quick Add and text editing remain available, including automatic text measurement. Unlock All operates on immediate children of the current scope: unlock the source wrapper from the library level, not from inside itself. Do not implement a blanket read-only workspace or propagate source editing locks into ordinary page instances. This explicit-entry comparison supersedes the earlier no-selection/clipped-state interpretation.

The core now implements independent source duplication and explicit library-root Group/Ungroup transactions, including ordinary library controls. Grouping preserves canonical child locks and nested instances instead of expanding the drawing. Duplication separately clears locks in its copied tree. Nested groups retain source names/notes; promotion back to sources creates fresh identities. One-source Group also creates a fresh outer source. Invalid coordinates, depth limits or unsupported root properties roll back the complete operation, allocator, context and history. Dedicated source panels are connected.

Model checks cover full notes, mixed source/control grouping, explicit paint order and nested instances. Native coverage remains narrower for nonempty notes, mixed-content placement/order and lifecycle. Owner-lock selection/rendering is integrated. Ordinary component workflows and verified shared root appearance remain intact.

Focused-source owner locks now protect geometry, movement/alignment, removal/grouping and component conversion. Native commands and inspector enabled states reflect those restrictions. Own-lock selection, text/property editing, automatic sizing and insertion remain available. Page instances retain independent locks. The bounded native macOS check covers selection, geometry, menu/inspector state, text/insertion and exact save/reopen preservation; clipboard destinations and remaining component action combinations still need targeted acceptance.

## Source clipboard

Navigator Copy exports canonical source content as a group, with source provenance. Library Paste promotes that group to a fresh independent source and resolves name collisions; focused-source and page Paste insert ordinary groups. Existing ordinary component-instance copy retains its established behavior. Root crop/content are preserved and copied locks clear. Preserve ordinary nested instances without recursively expanding them.

A cut source can leave references missing. If its same-project clipboard content is pasted as a new library source while the original is absent, reconnect those dependents to the new identity in the same transaction. Keep overrides intact. Undo must restore the exact prior graph, source identities, overrides, allocation and editing state; removal and paste are separate history entries. Invalid operations must be atomic.

Navigator source Cut is distinct from canvas child Cut under a locked owner. Child duplication and layer ordering remain allowed inside a locked source; geometry/removal protections continue. Navigator Duplicate must target the selected source consistently, including the first row. Naming uses a copy suffix with collision handling, distinct from canvas same-name duplication and paste collision naming.

The core implements this contract for single-source and same-library multiple-source payloads. It takes a project-origin value from its caller; absent or foreign values cannot reconnect existing references. Library/source/page target behavior, dependent retargeting, notes/crop, nested dependencies, exact history, scoped-ID allocation and atomic failure have model coverage. Application origin assignment, navigator commands and resource-aware offsets are implemented and have scoped native macOS acceptance. Library Paste of one source enters it with navigator focus and notes; Paste under a locked source owner clears canvas selection. Whole-library/cross-library clipboard uses the separate resource-transfer contract below. Cross-project link policy, exhaustive offsets and nested own-lock native behavior remain open. Same-library multiple-source flows have scoped native macOS acceptance. Known lossy history behavior is not a product requirement.

Source duplication corrections are implemented and covered by model/application checks: navigator and canvas naming differ, literal child locks clear without mutating shared dependencies, and source-focused child duplication offsets by ten units. Locked-owner child layer ordering remains available. Exact Undo/Redo, persistence, notes/crop, original page/source preservation, collision scope and first-row command targeting are covered. Combined native macOS duplication/clipboard acceptance passes; existing installed packages do not include it.

Source payloads use library coordinates. When pasted inside a focused source, subtract the destination owning placement origin as well as the entered group context. Content pasted into a library becomes a fresh source; top-level page content remains an ordinary group. Reconnecting an absent source updates dependent instances on pages, alternates, other definitions and ordinary library content without modifying their overrides. The entire import/promotion/reconnection is one history transaction. Existing clipboard JSON without source provenance remains readable; file format is unchanged.

## Multiple source clipboard contract

Multiple sources from one library use a single control clipboard containing canonical groups and per-source provenance. Both navigator multi-selection and selected library-canvas sources follow this content contract. Library Paste creates independent sources and retains the library canvas with the inserted roots selected when several controls are pasted. Page or focused-source Paste inserts ordinary groups; an unlocked focused source retains those selections. Do not enter only the last source after a multi-source paste. Copying across libraries or copying a whole library is a separate resource transfer, not this control clipboard.

Paste collision names compare case-insensitively within the destination library. A trailing numeric parenthesis suffix is replaced, starting at(1) and finding the first free candidate; otherwise append a space and(1). A noncolliding name remains unchanged. This rule is independent of explicit navigator Duplicate's copy suffix. This naming policy has regression coverage. Multiple-source payloads, navigator range/toggle selection and canonical library-canvas routing are now implemented, with scoped native macOS acceptance.

The multi-source implementation must keep a source-to-root mapping, validate every entry before any mutation, allocate/promote each source independently, and retarget each absent same-origin source atomically without changing local overrides. Preserve legacy single-source and ordinary control clipboards. Viewport clamping must use the full pasted selection bounds, not only its first root. Mixed ordinary library controls, cross-library/resource transfer, SaveAs origin continuity and complete multi-cut dependencies remain evidence/acceptance follow-ups.

Same-library multi-source Cut/Delete is one history entry. Pasted sources reconnect independently only when their same-origin originals are absent, leaving any original that still exists unchanged. If one restored source is also an imported dependency of another, coalesce that dependency into its restored identity rather than retaining a hidden duplicate. Reserve missing provenance identities before allocating after Undo. Reject duplicate/ambiguous metadata atomically. Single-root source clipboards keep their earlier encoding; older ordinary clipboards still decode.

After multi-root Paste, release navigator command focus so Copy/Cut operate on the selected canvas contents. The navigator supports Shift ranges and command-modified toggles within one library, preserving an explicit unselected context-row target. Global/keyboard navigator Duplicate is disabled for multiple selected sources. A row-context Duplicate remains enabled and acts only on that explicit source, then selects/enters its copy. Context Rename is disabled during multiple selection. Rendered menu and transaction tests cover this distinction. Cross-library selection/resource transfer is implemented under the whole-library contract below, with its own scoped native evidence. Native checks verify multiple-root selection, released navigator focus, exact document Undo and byte-identical fresh-process reopen/resave. Navigator range restoration after Undo remains a separate open detail.
