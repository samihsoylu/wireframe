## Project-copy foundation — W92

`Editor::prepare_project_copy` prepares an isolated result from explicitly selected live pages, all live component libraries and all assets. It preserves alternate versions, scoped node/override identities, page hierarchy among selected ancestors and internal links. Resources receive fresh IDs; identical assets and named versions can be shared. Omitted or previously removed link destinations retain distinct missing-page identities. Unavailable components remain unavailable, and orphan override IDs are reserved against future accidental reuse. Destination appearance settings and font remain authoritative.

The prepared result exposes its counts and preview without mutating either project. Applying it checks the exact destination snapshot and records one Import project history entry. Cancellation, stale preparation, invalid selections, ID exhaustion, invalid combined graphs and the serialized 64 MB limit cannot partially import. Empty import is a no-op. Whole-library origin records are retained for future conflict review; this API always copies rather than replacing existing pages or libraries.

Eight focused tests cover graph preservation, repeated Keep Both, identical and unused assets, missing destinations, orphan paths, cancellation, stale plans, file limits, exact Undo/Redo and save/reopen. Neighboring library-transfer and source-clipboard tests also pass. This is backend acceptance only. This Keep Both foundation is extended by the page-review API below. The combined planner, review integration and browser below now supply resource collision review, comment import, catalog selection, source-file guards and previews. Final native/platform acceptance remains open.

## Page collision review — W93

`Editor::plan_project_page_import` matches live destination pages by prior source correspondence first, then exact name among unclaimed pages. Trashed pages are excluded. Foreign numeric IDs alone do not identify the same resource across independent projects. Low-level preparation receives a decision for every matched page. The browser now supplies Use Existing automatically when a fully mapped replacement preserves the page, and presents Use New, Use Existing or Keep Both for actual differences.

Use New retains the destination page ID, name, order and parent, updates official content/notes and supplied alternate branches, and preserves unmatched local alternates. Known alternate identities remain stable. These retention rules were corrected in W94 after tracing the replacement path. Use Existing retains destination content and records source correspondence. Keep Both creates a fresh page. Incoming links, parent relationships and component-definition links resolve to the accepted destination page IDs; pre-existing destination content is not rewritten. Historical alternate correspondence survives removal and later re-import. Strong origin matches take priority over name matches for both pages and alternates.

Optional `page_imports` metadata is backward-compatible with files lacking it. Validation reserves historical alternate IDs, prevents cross-page ownership and rejects invalid or excessive correspondence. Permanent removal clears the page's metadata from current and historical snapshots; Trash retains it. PDF/raster projections omit project-only correspondence so individual pages and alternates can still export without changing the source project.

Planning and preparation are isolated. All choices, graph limits, hierarchy cycles and serialized file limits are checked before application. Replacement at the 1,000-page limit validates the final graph rather than rejecting temporary copies. Applying retains the existing exact-snapshot guard and one Import project history action. Repeated reuse with no other imported resources is a true no-op.

Eleven focused tests cover mixed choices, link remapping, retained local names/content, alternate rename/removal/return, origin priority, Trash/restore, permanent removal across history, stale or incomplete decisions, cycles, capacity, malformed metadata, PDF/raster output, exact Undo/Redo and save/reopen. Sixty-one neighboring copy, deletion, Trash, version and export checks also pass, plus 36 recovery checks (one helper ignored). All-target warnings-denied Clippy, formatting and diff checks pass. This is backend self-review, not native import-interface acceptance.

The earlier page-only API keeps its explicit-copy library policy. The combined review path described below adds library decisions and mapping. Source snapshots are immutable here; file-change detection belongs to the browser loader. Comment resources now follow page decisions through the integration described in [review comments](REVIEW-COMMENTS.md).

## Complete resource conflict contract — W94

Whole-project import must review assets, pages and complete component libraries together. Whole-library decisions differ from individual-source conflict choices. Assets match prior import correspondence before names; identical bytes can reuse a matched asset, while changed bytes need Use New, Use Existing or Keep Both. Asset replacement retains the destination identity and name so existing consumers continue to refer to it. W95 adds explicit asset review and persisted source correspondence through the page/import plan. The older explicit-copy API retains its byte-deduplication policy; see the current asset section below.

Replacement and addition have different metadata rules. Existing pages keep their name, tree position and order. Supplied branches update; unmatched local alternates survive. Explicitly empty incoming page notes clear the note; an omitted note is different at a foreign-format boundary. Native project files currently carry a concrete note string. Whole-library replacement keeps resource-level local notes and name while replacing source content. Individual source notes remain part of that content. New resources retain incoming metadata subject to collision naming, mapped parent IDs and insertion order.

W94 corrects page-parent/alternate retention and whole-library note retention. Twelve page-import, 31 library-import and eight project-copy tests pass. The library note-only propagated replacement now counts as reuse and creates no empty history action. These supersede W93's replacement of page parents/unmatched alternates and the older library expectation that local resource notes were overwritten.

Integration must create one final identity map across selected pages, all libraries/definitions and assets before mutating the destination. The library clipboard path deliberately strips foreign page links; whole-project import must instead map those links to accepted page destinations, including within nested definitions and override values. It must also translate override paths in incoming pages and alternates when they reference reused definitions, and include those paths in orphan-capture checks. Existing destination consumers must retain their valid local overrides, with explicit review of newly unresolved edits.

Build and validate one isolated final document; do not sequence public paste commands or create multiple history entries. Resolve all choices before applying one guarded Import project action. Automatic equivalence must account for the final resource mappings. Cancellation, malformed input and invalid choice combinations leave both projects untouched. Keep source-file change detection at the catalog/preview boundary. Native end-to-end review is still required; extracted source-method execution does not establish it.

## Asset decisions in project import — W95

`PageImportPlan::asset_entries` exposes Add, Reuse and Conflict actions. `prepare_with_assets` accepts page and image decisions together and returns one isolated, guarded project import. Prior source correspondence reserves targets before exact-name matching. Matched assets with equal media type and bytes reuse automatically; changed assets need Use New, Use Existing or Keep Both. Unknown or missing conflict decisions fail before application.

Use New updates bytes/media type while retaining the destination asset ID and local name, including existing consumers. Use Existing preserves local bytes and maps incoming references to that asset. Keep Both assigns an independent identity and collision-safe name. The same map reaches pages, alternates, library content, definitions, image properties, icons, icon lists and instance override values. All source assets are included, even unused ones, in line with complete-project import.

Optional `asset_imports` metadata records source-project/resource pairs under destination asset IDs. Old files without it still decode. Validation bounds records and rejects missing owners, invalid origins, zero foreign IDs and duplicate records. Foreign IDs do not occupy local allocator space. Source renames still match known provenance. The first reuse may add correspondence; subsequent unchanged reuse is a true no-op, with no allocation or empty history action. Recovery, named save/reopen and exact Undo/Redo retain the metadata.

The reviewed path keeps unmatched, differently named assets distinct even when bytes match. The pre-existing explicit-copy path still deduplicates bytes and now records correspondence for future review. Final graph and serialized file limits are checked after decisions: two individually saveable projects can reject Keep Both while permitting replacement within the file limit.

Seven focused tests cover mixed page/image choices, real rendered pixels and Undo, all image-reference forms, unused resources, source renames, strong-match priority, duplicate names, backward-compatible/invalid metadata, cancellation, stale decisions, recovery, save/reopen, no-op history and file limits. ## Offline product behavior

Ship original starter projects and support explicitly chosen local `.wireframe` projects. Catalog entries need a stable identity, title, category, description, preview and project content. Use no vendor catalog, service endpoint, branding or artwork. This content source is a deliberate offline adaptation; it does not imply an online marketplace or third-party project-format support. Existing-format import remains deferred.

Sort entries by title. Category selection filters the full collection. Nonempty search ignores the category filter, matches title/category/description without case sensitivity, and lists title matches before other matches while preserving title order within each group. Clearing search restores the selected category. The empty state must be explicit. Preserve search and category while moving between the list and a preview.

Preview must show the actual project content, support its pages and component libraries, and provide previous/next navigation within the visible results. Enable navigation only when a neighbor exists. The first preview resource is the first component library when the project has a library and exactly one page; otherwise use the first page. Back returns to the list. Close discards preview state without modifying either project.

Import is a complete resource operation, not insertion of a rendered thumbnail or only the displayed page. Include nonempty pages and pages with notes/comments, component libraries and image assets. Preserve page hierarchy, internal links, component dependencies, overrides, alternate content and asset references through ID remapping. Review collisions before any destination mutation; cancel leaves the destination untouched. Commit the complete accepted result as one history action, then verify Undo/Redo and save/reopen. Read-only preview loading must never acquire the source project's working-copy ownership or save to its path.

## Automatic reuse of unchanged pages

The browser compares an isolated candidate after page, image and component references and override paths have been mapped. It ignores scoped control identities while comparing effective paint order and complete control content. Unchanged pages and supplied alternates reuse without redundant choices. Explicit decisions remain authoritative, and changing a resource to Keep Both recalculates equivalence: a previously unchanged linking page may then require review because its target changed. No prepared graph is applied until all remaining conflicts and impact warnings are resolved.

Position, notes, alternate metadata and discussion changes still require a decision. This intentionally avoids silently discarding those changes; automatic reuse is stricter than a drawing-only comparison. Unknown/invalid provisional mappings retain explicit review and its existing error handling. Cancellation, history and source/destination guards remain in the shared import path.
