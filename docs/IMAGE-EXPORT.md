# Image export — implementation contract and current limits

The image-export workflow is implemented with source, behavior tests and scoped native PNG/ZIP/cancellation evidence. The current requirements audit retains both-platform passing tests for unchanged export code. Native macOS covers current/chosen pages and Active/Official/Current version helpers; native Linux covers shown/hidden current-page PNG with exact output comparison. Full native workflow and final release acceptance remain incomplete; historical installed copies are not evidence of the current candidate.

## Planning and rendering

`export_plan` supplies ordered official/alternate entries and validates all/current/chosen page requests. Chosen sets follow document order. Explicit alternate choices do not depend on an include-alternates flag. PDF retains its existing labels, default exclusion of alternates and1000-page limit. Image exports include alternates by default and do not inherit that PDF-only limit.

`raster::plan::Prepared` owns a private layout editor and an immutable document snapshot. It materializes complete page versions rather than deleting unselected controls from a page. A single current page may export its whole content, a group's children or selected control paths. Empty/stale selections, missing paths, a leaf used as a group, and a non-current/multiple-page scoped request return errors before publication.

`Editor::export_scene` filters canonical layers while preserving ancestor crops, original world positions, instance overrides and document paint order. It does not use transient editing dimming. Selected parent/child paths cannot duplicate artwork. Empty pages/groups use a minimum logical output extent of one, applied by the encoder. Whole-page bounds round up; group and control-selection bounds round to nearest before pixel density is applied.

The interactive editor should pass `export_snapshot()` to the background worker, which calls `Prepared::from_snapshot`. This retains each previously displayed clock/calendar value, captures one fallback time/date for unseen controls, and prevents subsequent editing from affecting export. `Prepared::new` supports a standalone document, capturing its dynamic values at preparation.

## Filenames and publication

`raster::names` generates NFC Unicode filenames, replaces forbidden/control characters, protects reserved device names and trailing spaces/dots, and bounds component length without splitting UTF-8 characters. Canonical Unicode/case comparisons disambiguate names after sanitization. Original numbered page names are reserved before duplicate suffixes are assigned. Archive paths contain one generated project folder and one generated filename. Full path limits still depend on the destination filesystem.

Naming rules are based on [Microsoft's filename documentation](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file). Normalization uses pinned unicode-normalization0.1.25; its upstream MIT/Apache notices are retained in the dependency inventory.

`raster::publication::PendingOutput` encodes into a temporary file beside the destination and synchronizes it before publication. New outputs use an exclusive publication operation; a destination appearing after encoding becomes a conflict. Explicit Replace swaps the complete output at that path and rejects folders/symbolic links. Keep Both reserves planned names, checks existing Unicode/case equivalents and retries exclusive publication when a candidate is taken by another writer. Skip/Cancel discard the temporary output. Cancellation during encoding propagates without publishing.

Replace is authorized replacement of a path, not a compare-and-swap against another program's simultaneous edits. Directory-name changes and external races beyond exclusive creation remain limitations. On Linux, a directory-sync failure after publication returns a saved-file result with a durability warning, rather than pretending the file was not written. Crash/power-loss, unusual/network filesystems and native publication-failure acceptance remain open. Windows native testing is held; the sampled Linux PNG export does not establish those failure paths. Temporary-file cleanup after a process crash is not guaranteed.

## Archives and background jobs

`raster::archive` streams each PNG directly into a ZIP entry in document order, under one generated project folder. It uses stored entries because PNG data is already compressed, reserves ZIP64 sizes and explicitly checks archive finalization. One scene/PNG stream is processed at a time. Pinned zip9.0.3 has optional compression/encryption features disabled; its own and added dependency notices are retained.

`raster::job::ExportJob` owns the snapshot on a worker. A file destination produces PNG for one selected page and ZIP for multiple pages; a folder produces individual PNGs. Progress is a single replaceable state, not an accumulating event queue. Conflict decisions carry IDs so stale/duplicate replies cannot authorize a later destination in the same job. Replace/Skip/Keep Both support Apply to all. Cancellation wakes a waiting conflict; dropping the job requests cooperative cancellation without blocking the UI.

The report counts committed pages and files separately. A completed but unpublished ZIP contributes zero exported pages. Individual outputs already published remain counted if a later page is cancelled or fails. Skipped pages and remaining pages are separate. Published pages reduced by the dimension limit are explicitly listed, and saved-file durability warnings remain attached to the report. Cancellation cannot interrupt a blocked filesystem call; it is checked between preparation, raster chunks, publication and conflicts.

## Application integration

The conflict/options dialog, per-project option persistence, background progress/cancellation and result reporting are connected to the application action. Deferred closing waits for success and is cancelled on failed/cancelled/warning results. Component workspaces retain their own surface identity. The Active helper captures the remembered version of each live page when the export review opens; subsequent navigation does not change that frozen set. The Current helper selects only the current surface. The application regression `remembered_versions_are_captured_for_active_and_current_image_export` covers these choices; this is implementation/event evidence, not a new native export-dialog acceptance claim. The new export workflow is not installed. Native current-page 1x PNG, chosen-page 2x opaque ZIP/order, empty-set disabling and save-panel cancellation have passed; full native acceptance remains open. Maximum-area and multi-gigabyte archive performance, native archive-reader/platform checks and filesystem failures beyond the exercised cases remain open.

The raster encoder supports explicit framing, 1x/2x and white/transparent output. Maintained regional extensions in vendor/resvg and vendor/tiny-skia preserve the full logical canvas/layer geometry while retaining only requested pixels. This corrects curve subdivision/quantization and nested layer bounds differences caused by changing the rasterization context for each output tile. Original regression tolerances remain unchanged.

The scene traversal supports generated paths, text, images, groups and clips; unsupported SVG filters, alpha masks and paint patterns return errors. See vendor/README.md for attribution and limits. Pixel buffers are regional, but path/scanline and decoded image/font resources have additional costs. Cancellation is checked between nodes and regions, not within a raster operation. Full maximum-area performance and memory acceptance remain open; rendering a small region of a 20000×20000 logical canvas does not establish complete 400-million-pixel PNG acceptance.

## Editor markup visibility

PNG and SVG output inherit the editor's current markup visibility. Image-worker snapshots capture it alongside document content and dynamic drawing values, so later toggles cannot alter queued output. `ExportSnapshot::with_markup` provides an explicit override. Hidden group/selection exports retain masks, placement and layer order; the canonical full scene remains available for thumbnails. `tests/markup_export.rs` checks bounds, links, PNG bytes, SVG, scope isolation and immutable capture. Native current-page shown/hidden PNG output now has paired bounds/placement evidence and current macOS/Linux byte-identical output. Current macOS also verifies Active/Official/Current version helpers with a hidden-markup cropped group: alternate60×60, official50×40 and ordinary100×30 outputs, ordered ZIP entries and identical Current/Active PNG bytes. The complete drawing is semantically unchanged after native close. External `interface-symbols-current/macos/export-variants/report.md` records scope and serialization normalization. PDF link/annotation, selected-child/component and imported-image-mask variants remain outside this native acceptance.

## Native folder conflicts and closing

The current macOS candidate verifies a three-page folder export with Replace, Skip and Keep Both in sequence. It preserves skipped/original files, generates the new name, and reports2 exported/1 skipped. Apply to all with Keep Both preserves all three originals and creates three outputs. Cancelling after the first publication keeps that output, leaves later originals intact and reports1 exported/2 remaining. A window-close request made while awaiting a conflict is cancelled with the export; successful Apply to all Replace finishes all outputs and then closes the window. Thirty-eight artifact/state/process assertions pass; all nine new PNGs are byte-identical300×80 images and the project remains semantically unchanged. Evidence: external native-export-conflicts-current/report.md.

This accepts those macOS dialog and image-export close sequences. Skip Apply to all, real filesystem failures, large-job sustained editing, PDF closing and other-platform native conflict behavior remain outside the replay. The earlier generic folder-conflict/successful-image-close gaps are superseded only for these named cases.

## Editable project destination protection

SVG, legacy PNG and the file-output worker routes reject a chosen destination equal to the open project or resolving to the same canonical path. The guard runs before output generation. Separate output replacement remains supported. This prevents the reproduced SVG route from replacing the editable project. Hard-link identity and external changes after validation are not established protections. File-backed regressions cover direct/parent-directory/symlink aliases and intact project data. Native macOS SVG save/cancel and standalone Zen rendering pass; native Linux PDF exercises the shared rejection through a symbolic-link destination. See external export-destination-current/report.md.
