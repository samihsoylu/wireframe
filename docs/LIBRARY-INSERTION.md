# Adding controls from the library

Quick Add searches catalog names and aliases, so searching for “Title” finds Heading. Exact matches precede partial matches. Arrow keys select a suggestion and Enter inserts it; Shift+Enter keeps explicit pointer placement.

Default insertion starts 50 screen points from the canvas's upper-left corner, accounting for zoom and pan. If that origin is occupied in the current editing context, it scans down in 50-point steps, then starts another column after the viewport's bottom. This avoids identical origins rather than all overlapping rectangles. The new control's measured size stays within the 10,000-unit canvas boundary; a repeated clamped position ends the search. Group insertion uses the same visible coordinates and remains one Undo step.

Drag a control onto the canvas to see it before releasing. A drag starts after movement exceeds six screen points; holding still does not start one, even after a long pause. The library uses compact 68×68 tiles, centered thumbnails in a 68×46 image area, and one-line labels with ellipses where needed. Hovering shows the full name.

The grab point is sampled when movement starts the drag inside the thumbnail image area, then stays attached to the floating control. Grab offsets include the padding around a fitted thumbnail. The floating preview uses full-size project artwork and retains its screen size across canvas zoom levels; placement converts its origin through the current zoom and pan. At the top or left canvas edge, the insertion origin is kept inside the viewport. The tile stays highlighted while held.

Release over the canvas to insert and select the control. Undo removes that insertion in one step. Escape, loss of app focus, or release outside the canvas cancels without editing the project. Double-click still inserts at the default position. A gesture confined to the label does not start a drag; moving from the label into the thumbnail can start one.

The preview is transient: it never enters the document, undo history, recovery file or export. Release commits before canvas painting to avoid an empty frame between preview and placed control. The source geometry and chosen grab offset are retained until release/cancellation. Fast gestures that jump directly out of the image area use their original image-area press as a fallback, so coalesced or split-frame input still inserts reliably. Motion before the press and after the release is excluded. A gesture that crosses the movement threshold and returns to its start remains a drag. Placement uses the release event position, even if subsequent hover motion arrives in the same frame.

Saving or opening a decision/recovery dialog ends active pointer gestures. A held preview cannot insert afterward, and canvas edge scrolling stops at the last visible edit captured by Save.

Validation covers activation-point sampling, image-area versus label gestures, save boundaries, fitted-image geometry, padding grabs, clamped edge drops, real egui events across frames, preview paint bounds following the pointer at 50/100/200% zoom, panning, cancellation, coalesced/split-frame drags, long stationary holds followed by movement, returned excursions, release followed by hover motion, and one-step history. Native macOS checks cover final placement and Undo/Redo. A later user-operated study confirms visible and smooth held previews, unchanged documents while held, stable grab offsets, four single canvas insertions and three no-op library releases. Sparse framebuffer captures show preview onset and release; continuous held state plus direct user feedback establish the longer hold. Current drag/scroll source matches that study. The complete revision-1.004 build also passes native single insertion, exact Undo/Redo, no-op inspector and beyond-window releases, and a subsequent single insertion without residual drag state. These atomic release checks do not establish held exit/reentry or cadence. Exact comparative onset timing, uninstrumented frame cadence, display-pixel alignment, library autoscroll and native Windows/Linux acceptance remain outstanding. Existing-control edge scrolling is a separate behavior; library insertion does not currently use it.

## Component entries

The same tile, placement and gesture path now accepts reusable component identities. Previews represent fresh instances with crop/root appearance and nested content. Self/dependent sources and whole-library destinations are disabled; Quick Add excludes unavailable entries. A captured source/context/session or preview change cancels the gesture before insertion. Category changes also end gestures. Tests cover component events at 50/100/200% zoom, coalesced input, one-step Undo and stale payloads. Native component drop checks establish final placement and Undo only; the earlier physical held-preview study covers built-in controls.
