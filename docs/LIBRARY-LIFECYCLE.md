# Component library lifecycle

## Required behavior

Move Library to Trash retains the complete library, owned source definitions, source placements, notes, locks, crop, provenance and assets with their original identities. Hide it from the active navigator and insertion catalog. Its sources are unavailable to normal instance resolution, so existing uses display the missing-component state while retaining their original references and overrides in storage. Restoration reactivates the same graph and repairs those uses without rewriting their saved data. Retained state must survive save/reopen and process restart. Include libraries in the shared Trash browser with explicit restoration.

Cut uses the resource clipboard scope established by library transfer: a selected library or sources across owners includes each complete owning library. Publish the complete clipboard successfully before removing any content. Remove the selected library resources and their owned definitions from the document in one undoable transaction; do not retain a second Trash copy. References in other surfaces remain unresolved with their original identities and overrides. Do not remove unrelated dependency libraries included only to make the clipboard self-contained. Preserve assets still used elsewhere or needed by history.

Pasting a cut library at the same named-project origin restores its absent identity and reconnects uses. Pasting while the original identity is retained in Trash creates a fresh live copy and leaves the original retained. A retained library still occupies its identities; never replace it or capture its consumers accidentally. Same-project Copy/Paste and dependency-only reuse rules remain in effect. Validate the whole resulting graph before one exact Undo/Redo transaction. Keep crop and override data intact even while the visual representation is missing.

Source-only deletion and library Trash are different commands. Do not infer Delete selection scope from the whole-owner clipboard resolver. Existing same-owner source actions remain available. Mixed and multi-owner context removal is accepted below; the global keyboard route remains gated. Permanent deletion is implemented through the shared confirmation and history sanitation described in [permanent removal](PERMANENT-REMOVAL.md); native library deletion remains unverified.

A source context menu deletes its selected source rows, including across owners, while leaving each library live. An unselected context target acts alone. The existing model transactions provide one-step Undo/Redo for each requested set. Global Delete availability is unchanged; the internal presence of a mixed-removal handler is not evidence for enabling a keyboard route.
