# Page navigator rendering

The navigator collects page identity and captions without copying page contents. List mode uses metadata only. Thumbnail rows keep their layout, selection, accessibility labels and context menus while drawing artwork only when their rectangles intersect the visible viewport. Scrolling a row into view requests its current scene through the normal layout/rendering path. Dynamic values are captured when the scene is first rendered. Existing content, version, project-font and palette invalidation continues to apply.

Application regressions cover visible-only dynamic rendering, long scrolling, list-to-tile transitions and document preservation. An optimized native macOS check covers 115 pages, distant-page selection, version context menus, list/tile changes and unchanged Save. Its initial contact canvas matches the earlier capture pixel-for-pixel.

A scoped CPU study measures warm 115-page updates at 1.34 ms with thumbnails and 0.60 ms in List mode, versus 14.61 ms and 7.98 ms previously. It excludes GPU presentation, native event delivery, persistence and library. Dense visible thumbnails remain expensive; this change is not full performance acceptance. No thumbnail cache or artwork-quality reduction is used.

## Hierarchical interaction contract

Current page, selected page IDs and expansion state are distinct. Ordinary click selects one expanded row or the entire subtree of a collapsed row. Command-click toggles that scope while preserving the active page. Shift-click extends from the active page across visible rows and includes descendants hidden beneath selected closed rows. Context actions on a selected row use the selection; an unselected expanded row targets itself, while an unselected collapsed parent targets its subtree. Count-aware menus disable single-page rename/alternate actions for multiple selection.

Collapsing the active child's parent switches the canvas to that parent and selects its subtree. Expanding the active parent selects only that parent. Toggling an unrelated branch reduces selection to the active page. List/thumbnail changes preserve expansion state. Native evidence shows indented child rows/cards and visible disclosure controls. Expansion persistence, drag reordering and depth handling are implemented below; sampled macOS restart acceptance is recorded below; the later fast-drag section adds sampled native ordering coverage; held-preview and depth-boundary cases remain open.

Duplicate operates on an explicit ordered selection. A single expanded parent is copied after its complete original subtree without its children. A collapsed subtree is copied as a new subtree with new page/alternate identities and shared dependencies. Arbitrary disjoint copies reconstruct the relative sequence of selected depths, then attach after the last selected ancestor at the shallowest selected depth; merely remapping original parent IDs is insufficient. First execution selects all copies and activates the first. The established subtree Undo case returns to the last original child and expands its parent; Redo selects both copies and activates the first. Complete arbitrary sparse-depth and history cases must be verified alongside the batch implementation.

The navigator now implements this pointer selection/expansion/context scope and batch duplication. PageTree is a read-only live projection; hidden or later parent identities remain stored without creating visible ancestry. Page-focused Select All, Duplicate and Trash route through page operations. Whole-page Cut/Copy/Paste is implemented below; grouping remains a canvas operation. Text fields keep their editing commands.

## Ordering and rename integration

The editor moves an explicit live selection before a gap in canonical live-tree order. Selection is normalized and stale/retained targets or unavailable gaps fail without partial changes. A moved expanded parent leaves unselected children with the nearest preceding eligible peer or shallower ancestor. Selected internal relationships travel together; sparse selections reconnect to preceding selected ancestors. Dropping before a child adopts that child's parent; dropping at the end places moving roots at the root level. Visible gaps after a closed branch skip its hidden descendants.

Indent/outdent operate on the explicit selection without reordering rows. Eligibility is determined from the original tree, shallowest levels first, with a five-level indent limit. Indenting a parent alone makes its existing children siblings; including them in the operation retains the selected branch. Outdenting adopts following siblings as children. The transactions preserve page identities/content, shared dependencies, active alternate and current control selection. Retained pages keep their exact slots and stored ancestry. Saved round trips and repeated Undo/Redo are checked. Canonical live ancestry is written only when an operation changes the live order or hierarchy; no-op operations preserve Redo.

List and thumbnail rows now start a drag after the framework's movement threshold. While held, a caption follows the pointer and a line marks the insertion gap; the document changes only on a valid release. Edge scrolling follows elapsed frame time. Existing selection determines the drag scope; an unselected closed row contributes its complete branch. The current canvas remains active. Dropping preserves collapsed branches and reveals the active page's ancestors. Escape, focus loss, outside release, disabled UI, changed tree or a replaced project session cancels without a document mutation. Keyboard/document commands cannot execute beneath a held page drag.

F2 and Command/Control-Alt-R open the current page's existing rename dialog when the page navigator owns focus and no canvas controls are selected. Text fields, popups and modal boundaries retain their own commands. These routes do not change the document before rename confirmation.

This supersedes the earlier implementation gaps for drag/reorder and rename shortcuts. Native drag cadence, preview/marker fidelity, edge scrolling, cross-platform focus and keyboard acceptance remain open. ## Indent keys and lifecycle focus

Tab indents and Shift-Tab outdents while the page navigator owns keyboard focus. The delivered Tab event is consumed by page navigation; Shift determines direction. Existing text editors, popups and modal guards keep their own input. Hidden selected descendants become visible after the operation. Selection, current page and keyboard ownership remain stable, including no-op limits. Every changed action is one history step.

Batch outdent is not necessarily the inverse of batch indent: each eligible selected level moves after its selected ancestor has moved, so a selected chain can become root siblings. Undo restores the exact prior hierarchy. Tests distinguish these operations explicitly.

A navigator-owned lifecycle/history change now transfers keyboard focus to the resulting current row. Delete, Duplicate and Undo/Redo remain available to the page workflow immediately afterward. Changes initiated with another widget focused do not acquire page focus. This fixes the reproduced case where deleting the focused page left no page command owner.

## Save and rename focus boundaries

Explicit Save retains the page keyboard owner through the asynchronous save modal. Capture happens in the same drawing pass that opens the modal, covering completion before the next frame as well as a slower worker. Restoration happens before the next shortcut and again during row construction, because the closing modal still blocks widget interaction for one pass. A new focus owner, error dialog or replaced project prevents restoration of the old owner. Text fields retain their separate input-ordering behavior.

Page rename returns keyboard ownership on both Cancel/Escape and successful Rename/Return. Keyboard and page-context entry points retain the originating row; project and component rename do not acquire page ownership. Cancel preserves project bytes/history; commit remains one undoable rename.
