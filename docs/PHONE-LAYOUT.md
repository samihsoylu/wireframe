# Phone frames

Phone has four models: Classic (282×510), Tall (282×573), Wide (380×754) and Notched (436×867). New controls use Notched with Stretch. Older controls without explicit device properties use Classic with Maintain proportions; saved dimensions remain intact.

The inspector provides model, orientation, resizing mode, five background patterns, transparent screen and status bar. Automatic dimensions follow the selected model and orientation. Manual dimensions survive later property changes; Auto-size restores intrinsic dimensions. Maintain proportions centers the frame inside the control. Stretch preserves frame sections and compresses opposing sections when space is limited. Model/style size gates hide status content and frame details when necessary.

Transparent screen removes the base fill while retaining the frame, pattern bars and status content. Status text uses shared font measurements. Canvas, library thumbnails, page thumbnails, SVG and PNG share original vector contours and layout. A single indexed mesh forms the frame around the screen opening, avoiding seams and preserving underlying content. Original icons and frame details are drawn in code; no external device artwork is embedded.

The notched frame uses rounded shoulders, short vertical necks and larger rounded lower corners. Each bend is sampled separately so it stays curved in both drawing styles. The same contour follows the existing portrait/landscape and fit/stretch transforms; its screen opening remains transparent.

The pure engine in `src/phone.rs` returns frame bounds, screen geometry, ordered fills, status positions, detail placements and proximity guides. Guides are local left/top/right/bottom coordinates. `src/render/phone.rs` maps independent artwork to this layout. Local component edits remain sparse overrides; reset, history and project storage use the shared editor mechanisms.

Twelve focused tests cover geometry gates, centered fit, stored/insertion defaults, transparent pattern compositing, seamless frame strips, automatic/fixed dimensions, Undo/Redo, legacy files, local overrides, invalid edits, small bounds, finite clipped rendering and exterior spacing guides. Raster checks distinguish the notch's vertical neck from a diagonal edge and verify its opening and solid frame in both orientations, resizing modes and styles. Earlier native macOS checks cover library insertion, model/orientation sizing, fixed dimensions, proportional mode, transparency Undo/Redo, both gallery styles, four exports and restart/resave. Those four native exports matched their generated files byte for byte at that checkpoint.

This is scoped implementation acceptance. The notched contour has additional scenario-level visual acceptance; exact frame/detail weights, status glyph shapes, nested clipping and broader native interior-guide snapping still need verification. Native Windows/Linux execution remains unverified. Reproduce the gallery with `cargo run --example render_phones -- <output-directory>`.
