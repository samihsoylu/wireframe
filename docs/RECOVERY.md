# Local recovery lifecycle

The workspace keeps one atomically written recovery project under an exclusive process lock. Dirty documents are checkpointed on the five-second write interval; unchanged snapshots are not rewritten. Undo returning to the saved document removes the older recovery immediately. Save, explicit discard and successful project replacement clear the active snapshot.

The shutdown callback flushes the latest unsaved document, including changes newer than the interval. An explicit quit/discard prevents that callback from recreating discarded work. An unresolved startup recovery offer blocks recovery writes and survives loading a startup file or closing the window. Restore opens it as a new unsaved project and does not overwrite the source file. Start fresh explicitly removes the offer.

An unreadable recovery file is moved to a unique `unreadable-recovery-*.wireframe` beside the normal recovery file before new work can use that slot. A startup notice gives its location; the original bytes are retained, not decoded and rewritten. Existing archives are never replaced. If preservation fails, the original stays in place and automatic recovery is disabled for that session with a manual-save notice. Missing recovery files are normal. The exclusive lock still prevents a second process from changing the checkpoint.

Native macOS verification used an isolated malformed file, confirmed its preserved bytes, created new work, quit/restarted, restored that new work and saved it byte-identically. The active recovery cleared after Save while the unreadable original remained. Preservation failures and repeated unreadable files have automated coverage. No corrupt file was repaired, and no power-loss guarantee is claimed.

Failed writes retain the previous snapshot and are retried. Failed removal is reported in the status line and retains the in-memory snapshot marker for retry. These operations do not modify the saved project.

Seven regression tests cover unreadable-file preservation, unique archives, failed preservation with manual saving, clean Undo followed by dirty Redo and immediate exit/reopen, pending-offer preservation, explicit discard, and failed recovery write/retry. Native macOS tests created a synthetic checkbox, observed its snapshot, undid to clean and verified file removal, redid and quit, reopened/restored the edit, closed an unresolved offer and verified byte preservation, then explicitly discarded the restored test through the normal close prompt. The current full suite passes 458 tests, including 53 app tests and seven recovery tests; all-target Clippy is warning-free.

Limitations: forced process termination can lose changes since the latest completed checkpoint. Native macOS Cmd-Q currently exits without the app's Save/Discard/Cancel prompt; the shutdown callback preserves the current document as recovery. Window close shows that prompt. Native quit-dialog integration and Windows/Linux lifecycle checks remain acceptance work. Per-project working copies, automatic synchronization to named project files, externally changed saved files and fallback between saved/recovery versions still need broader lifecycle acceptance.
