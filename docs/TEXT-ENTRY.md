# Text entry

Freeform input uses a source-based editor: control text, project/page/component names, notes, Quick Add, icon search, segment URLs, and project-font names/notices. Numeric steppers retain their framework editing behavior. `text_entry::Draft` owns the original UTF-8, selection, and undo history. `text_entry::layout` shapes and rasterizes through COSMIC Text; its stock editing model is not used. `text_entry::widget` connects pointer, keyboard, clipboard, composition, and accessibility events to Draft.

Grapheme ranges map original source to visual cells. Caret affinity distinguishes the two sides of a directional or wrapped boundary. Multiple glyphs belonging to one grapheme share one cell; ligatures spanning multiple graphemes divide their advance. Trimmed wrapping spaces retain zero-width source cells. Selection highlights follow visual cells, while clipboard text retains logical source order. The input layout and raster use the same physical scale and viewport.

The editor supports complete-grapheme deletion, reversible replacement, visual arrow movement, vertical movement, word and line deletion, selection, clipboard, and scrolling. IME preedit is temporary and its commit is one undo transaction. Accessibility text runs preserve source and line endings; selection actions map run positions back to UTF-8. Very long combining sequences are split at scalar boundaries to fit accessibility length limits, while editing still clamps to grapheme boundaries.

`TextInput` supplies single-line and multiline modes, requested width/rows, stable identity, one-time autofocus and placeholders. Single-line mode disables soft wrapping, scrolls horizontally, retains pasted line breaks, and exposes Enter/Up/Down to the containing form. Enter commits names; Quick Add uses vertical arrows and Enter for suggestions. Composition candidate keys stay inside the field. Registered input focus distinguishes text editing from buttons and popups when routing document shortcuts.

Input that precedes a focus-changing pointer action or window deactivation is applied before the transition. Window-focus events are processed in order: the final inactive frame state does not discard its earlier text, and text while inactive or before reactivation is ignored. Within a field-to-field batch, text and editing keys stay on their own side of the pointer boundary; consuming one key does not remove a matching key destined for another field. Tab delivers following input after focus traversal completes, including wraparound. Idle frames retain active IME composition.

Save, New Project, New Page, Open, navigator/library/inspector toggles and Present split the incoming event stream before the UI derives pointer/focus state. Earlier field edits reach the model before a command captures it or removes the field; later input remains after that command. This prevents immediate New Page or Present from losing the last inspector edit, and makes New Project detect newly typed unsaved work. Save preserves its prefix snapshot while later typing or local Undo stays after it. If the save worker temporarily disables the UI, the input owner and queued/new field input are retained until it finishes. Source-editor registration is restored before dispatching document shortcuts, so local Undo remains local.

The existing UI font is loaded with system font fallback. No project font is installed globally. Layout accepts at most 1 MiB of text, finite bounded dimensions, and raster images up to 8 million pixels. Draft history is bounded separately. Glyph caches and full-document shaping still need performance acceptance for large documents.

The in-window File menu temporarily owns input without accepting a canvas text draft. Ordinary Save persists the committed document, then returns focus to the draft. Escape while File is open closes the menu first. Background saving retains the focus-restoration request through the transient saving modal until the source field can receive input. Other root-menu transitions are outside this scoped correction.

Focused canvas Escape, single-line Return and Command-Return are input-order boundaries. Earlier typing reaches the draft first; following commands run after cancellation or acceptance and focus transfer. This keeps rapid Undo/Redo and Save on the correct document history. Ordinary multiline Return stays inside the draft. Eight full-application exit/history/save cases and a multiline newline/local-Undo case pass; the consolidated native batch verifies ordinary exit/history/save outcomes on both platforms. Exact same-frame ordering is established by the deterministic cases, not by native typing cadence (external text-exit-order-current and consolidated-candidate-current).

## Interaction fidelity boundary

The compact canvas text session now uses an anchored foreground popup without a dimming modal or Apply/Cancel buttons. Existing text is selected on entry and a grapheme count is shown. A separate scene renders the draft; the saved project and document history remain unchanged until acceptance. Return accepts a single line, Return inserts a newline for multiline controls, Command-Return accepts, and Escape discards. A pointer click or accessible activation outside accepts before the target handles the same action. Accessible activation inside the editor keeps the draft open. Window-close review commits ordered pending text before deciding whether to save.

Native macOS replay verifies entry/replacement, outside click selecting another control or clearing selection, Escape, single-line Return, multiline Return/Command-Return, and document Undo. Event tests verify preview text without document mutation, cancellation preserving Redo, stale-session rejection and close-window handling. The current application suite passes397 tests, with one preexisting opt-in graphics test ignored. An integrated native check verifies accessible page switching commits the draft, saves it with unchanged origin, supports one-step document Undo/Redo and retains the edit after full quit/reopen. Both list and thumbnail activation have same-frame input regression coverage. Native preview visibility beneath an overlapping popup, exact preferred placement across controls, auto-size/origin, linked rows/icons, all menu/save boundaries, native IME and other platforms remain outside this acceptance. Prior Apply/Cancel observations describe the superseded UI, not the current session.

Plain Icon double-click now opens the icon library; its sampled native apply/cancel/Undo flow passes. See [interaction acceptance](INTERACTION-ACCEPTANCE.md). No complete behavioral equivalence is claimed.

Both native menu and Command-Shift-S use the same command; ordinary Save retains its provisional-draft behavior. A later isolated manual-save comparison establishes that ordinary Save writes earlier committed changes while leaving the current canvas draft open. The Save command and keyboard route now allow that action through the existing modal/gesture guards. The strengthened regression starts with a genuinely unsaved committed change and checks keyboard/native dispatch with synchronous and background saving, continued typing, Escape and document Undo/Redo. Native macOS confirms both Command-S and File Save write only the committed change, with the draft still open. The corrected Linux in-window File menu and Ctrl-S now have native acceptance for saving earlier committed content while preserving the active draft and continued typing, including background-save focus restoration (external in-window-save-menu-current/report.md). Other active modal/gesture guards remain enforced.

Full-application regressions cover same-frame input before keyboard/native command, cancellation/success, manual-save path contents, exact history and unchanged ordinary Save. Thirty-five affected checks pass. Native macOS verifies chooser delivery, cancellation/reopened text, Undo, menu availability, Unicode copy, exact saved Undo/Redo and cold reopen. External focus-boundaries/report.md owns evidence. The subsequent controlled automatic/manual comparison closes the original-write discrepancy: automatic Save As writes both files, while manual mode leaves the original unchanged. Source failure preserves the new copy with a warning. See PROJECT-SESSION.md and external focus-boundaries/save-as-modes/report.md; no complete persistence or other-platform equivalence is claimed.

Application tests verify the preview glyph positions equal the committed scene and leave the saved project unchanged during the draft.

A List text session carries selection, row links and row icons together. ## Caret feedback

The shared source editor now honors interface blink durations and the steady-caret setting. Typing, selection changes and focus acquisition reset the visible phase. Disabled fields and inactive windows hide the caret and do not schedule its blink redraws. Input-method candidate geometry remains available while an active caret is in its invisible phase; text/history and caret geometry are unchanged.
